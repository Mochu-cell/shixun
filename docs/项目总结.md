# 医疗医保大数据与脑肿瘤影像智能检测系统 — 项目总结

> 本文档是项目的总览与交接材料，涵盖项目概览、系统架构、目录结构、功能模块、脚本使用说明、环境信息、运行方式与常见问题。完整运行命令见 [README.md](../README.md)。

## 一、项目概览

本项目是一个医疗医保大数据分析与脑肿瘤影像智能检测系统，覆盖“数据采集 → 清洗脱敏 → 数仓建模 → 分析挖掘 → 模型训练 → Web 展示”全链路，包含两大核心模块：

- **医保大数据分析**：以参保人、就诊记录、费用明细三张原始 CSV 为基础，完成数据清洗、脱敏、标准化，构建 ODS→DWD→DM 三层 Hive 数仓，产出 12 个分析主题与 4 张 MySQL 报表，并以 Flask + ECharts 仪表盘可视化医保 KPI、月度趋势、医院热力图、高风险人员名单等。
- **脑肿瘤影像智能检测**：基于 7200 张脑肿瘤 MRI 图像（胶质瘤/脑膜瘤/无肿瘤/垂体瘤四类）训练 YOLOv11 检测模型，mAP50 达 99.50%、mAP50-95 达 99.49%，并提供图像上传检测 Web 服务与综合仪表盘。

**核心成果**：3 个 Flask Web 应用、Spark MLlib 异常检测与费用预测模型、完整可复现的 Hive 数仓与 ETL 流程、99.5% 精度的脑肿瘤检测模型。

## 三、系统架构

系统采用经典四层架构：

```
┌────────────────────────────────────────────────────────────┐
│  前端层  HTML + CSS + JavaScript + ECharts（仪表盘/检测页）    │
├────────────────────────────────────────────────────────────┤
│  后端层  Flask（医保仪表盘 / 脑肿瘤检测 / 综合仪表盘）           │
├────────────────────────────────────────────────────────────┤
│  模型层  YOLOv11 脑肿瘤检测 + Spark MLlib 异常检测/费用预测     │
├────────────────────────────────────────────────────────────┤
│  数据层  HDFS / Hive（ODS·DWD·DM）/ MySQL / SQLite          │
└────────────────────────────────────────────────────────────┘
```

数据流向：原始 CSV → Hive 数仓分层 → MySQL 报表 → Flask API → ECharts 仪表盘；MRI 数据集 → YOLO 训练 → best.pt → Flask 推理接口 → 结果可视化与统计入库。

## 五、Hive 数仓分层

| 分层 | 库名 | 表 | 说明 |
|------|------|-----|------|
| ODS | `ods` | ods_insurance_info、ods_medical_record、ods_expense_detail | 原始三表，与 CSV 1:1 映射，按日分区 |
| DWD | `dwd` | dwd_insurance_detail | 三表 JOIN 宽表，衍生年龄段/参保月数/医院等级/报销率等 |
| DM | `dm` | dm_insurance_stats、dm_hospital_stats、dm_cost_analysis、dm_reimburse_analysis | 参保人/医院/月度/报销四维聚合 |
| 报表 | MySQL `data` | rpt_* 4 张、high_risk_person、tumor_* 4 张 | 供仪表盘与高风险分析使用 |

## 六、系统功能模块

| 数仓与 ETL | ODS 建表导入 → DWD 宽表 → DM 聚合 → MySQL 报表，完整 Hive/Spark SQL 流程，另提供本地模拟版 |

| 影像分析与训练 | OpenCV 对 MRI 做类别/尺寸/面积/位置分析；YOLOv11 训练与评估（mAP50 99.5%） |

### 8.1 开发机（Windows 11）

| 环境 | 用途 | 关键库 |

| 系统 Python | 数据分析、Web、SSH 脚本 | pandas、matplotlib、opencv-python、scikit-learn、flask、pymysql |

### 8.2 大数据环境（CentOS 7）

| 组件 | 说明 |
|------|------|
| Hadoop | `/export/servers/hadoop/`（伪分布式；HDFS 进程需 root 启动） |
| Spark | `/export/servers/spark/`（3.5.2；spark-submit 需完整路径） |
| Hive | 通过 `spark-sql` 访问，元数据库为 MySQL `hive` 库（持久化） |
| MySQL | 8.0.13，数据库 `data`（报表）+ `hive`（元数据） |
| Python 3 | `/export/servers/python38/bin/python3`（3.8.12） |

**关键注意事项**：
- Hive/spark-sql 必须用 `hadoop` 用户执行，否则会创建本地 Derby 元数据库导致看不到表。
- 含 `DROP TABLE` 的 DDL 脚本在有数据时不要重跑，只执行 HQL ETL。
- 精简版系统无 `grep`，文本处理用 `python3 -c` 替代。

### 8.3 MySQL `data` 库主要表

| 表名 | 说明 |
|------|------|
| rpt_insurance_stats / rpt_hospital_stats / rpt_cost_analysis / rpt_reimburse_analysis | DM 层 4 张报表 |
| high_risk_person | 高风险人员名单（417 条） |
| tumor_detection_stats / tumor_type_distribution / detection_confidence / patient_summary | 脑肿瘤检测统计表 |

### 8.4 敏感信息配置

仓库不包含任何真实密码/IP。运行前：

1. 复制 `config/local_config.example.py` 为 `config/local_config.py` 并填写真实值（该文件被 .gitignore 忽略）；
2. 或设置环境变量 `MYSQL_HOST`、`MYSQL_PASSWORD`、`VM_HOST`、`VM_PASSWORD` 等；
3. Shell 脚本执行前 `export MYSQL_PASS=<你的MySQL密码>`。

## 十、常见问题

1. **VM 未开机**：检查 VMware 中 CentOS 是否运行。
2. **Hadoop 未启动**：以 root 执行 `/export/servers/hadoop/sbin/start-dfs.sh`。
3. **MySQL 连接失败**：检查 `systemctl status mysqld` 及凭据配置。
4. **Spark job 报错**：使用完整路径 `/export/servers/spark/bin/spark-submit`。
5. **仪表盘无数据**：确认 VM 运行中、MySQL 服务正常、报表表已导入。
6. **CSV 列名混入数据**：Spark 导出默认带表头，导入 MySQL 前需预处理为管道符分隔。
7. **Hive 看不到表**：必须用 `hadoop` 用户执行 spark-sql（勿用 root）。
8. **YOLO 训练 OMP 报错**：设置 `$env:KMP_DUPLICATE_LIB_OK="TRUE"`。
9. **无 GPU 训练**：修改 `models/brain_tumor_detection/configs/training_config.yaml` 为 `device: cpu`、小 batch。

## 十一、给后续维护者的提示

1. 遵循模块化目录，新增内容按 `data/scripts/sql/models/web/docs/reports/config` 归类，不要按日期建目录。
2. 敏感凭据统一走环境变量或 `config/local_config.py`，严禁写入代码与文档。
3. 脚本一律使用相对路径（以仓库根目录为基准），保证换机器可运行。
4. Web 上传/结果目录（`web/detection/static/uploads|results`）为运行时产物，已加入 .gitignore。
